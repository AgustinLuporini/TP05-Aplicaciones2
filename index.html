Análisis de Trade-Off: REST Polling (500ms) vs WebSocket (10 Hz)

Polling REST tradicional (Pull @ 500ms)

  • Mecanismo: Peticiones HTTP GET periódicas enviadas por el cliente usando setInterval.
  • Ventajas: Implementación trivial, compatible con proxies y firewalls estándar, sin mantenimiento de conexión persistente.
  • Desventajas: Overhead repetido de encabezados HTTP (TCP Handshake / SSL), sobrecarga del servidor con 2 requests/s por cliente, mayor latencia para eventos críticos.

API WebSocket Nativa (Push @ 10 Hz / 100ms)

  • Mecanismo: Conexión bidireccional y persistente sobre TCP a 10 Hz mediante protocolo ws://.
  • Ventajas: Streaming en tiempo real real, latencia mínima (~10ms), mínimo overhead por frame (solamente 2-6 bytes de frame WS en lugar de kilobytes HTTP).
  • Desventajas: Requiere gestión activa del estado de conexión (reconexiones), consumo continuo de socket en backend.
